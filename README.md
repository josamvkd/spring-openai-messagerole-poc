# Spring Boot OpenAI Message Roles POC

A Proof of Concept (POC) demonstrating how to integrate **OpenAI message roles** with **Spring Boot** and **Spring AI**. This project explores System and User messages, role-based prompt construction, custom AI instructions, prompt customization, and AI-generated responses.

The implementation uses an insurance policy claim scenario to demonstrate how different prompt construction approaches influence the AI assistant's responses.

## Overview

In Large Language Model (LLM) applications, messages are assigned different roles to define how the model should interpret instructions and user input.

This POC demonstrates the following message roles:

| Message Role | Purpose |
|---|---|
| **System** | Defines the AI assistant's behaviour, instructions, and response guidelines. |
| **User** | Provides the user's questions, inputs, and additional context. |
| **Assistant** | Represents the response generated by the AI model. |

## Key Features

- Integration of OpenAI APIs with Spring Boot using Spring AI.
- Demonstration of System and User message roles.
- Multiple approaches to constructing prompts using `ChatClient`.
- Creating prompts using `SystemMessage`, `UserMessage`, and `Prompt`.
- Defining AI assistant behaviour through System messages.
- Supplying business context and customer input through User messages.
- Customizing and replacing system instructions for individual requests.
- Retrieving AI-generated content as a `String`.
- Retrieving the complete AI response using `ChatResponse`.

## Project Scenario: Insurance Policy Claim Assistant

This POC uses a sample insurance policy to demonstrate how an AI assistant can process customer questions using predefined policy information.

### Sample Policy Details

```text
Policy Details:
Policy: Premium
Maximum Coverage: 200000
Claim Amount: 250000
```

The customer provides a message, and the AI assistant receives both the policy context and the customer's input.

### System Message

The System message defines the assistant's role and establishes response guidelines.

```text
You are an insurance assistant.

You must NEVER reveal internal policy number,
calculations, or internal reasoning.

Respond ONLY with short, customer-safe messages.
```

### User Message

The User message contains the policy details and the customer's question.

Example:

```text
Policy details:
Policy: Premium
Maximum Coverage: 200000
Claim Amount: 250000

Customer says:
My claim amount is 250000. Can I claim the full amount?
```

The AI model uses the supplied instructions and context to generate an appropriate response.

## Implementation: Five Approaches to Message Roles

The `MessageRolesService` demonstrates five different approaches to interacting with the Spring AI `ChatClient`.

### 1. Creating a Prompt Using SystemMessage and UserMessage

Method: `checkPolicy()`

This approach explicitly creates `SystemMessage` and `UserMessage` objects and combines them into a `Prompt`.

```java
SystemMessage systemMessage = new SystemMessage("""
        You are an insurance assistant.
        You must NEVER reveal internal policy number,
        calculations, or internal reasoning.
        Respond ONLY with short, customer-safe messages.
        """);

UserMessage userMessage = new UserMessage("""
        %s
        Customer says:
        %s
        """.formatted(CLAIM_DETAILS, message));

Prompt prompt = new Prompt(List.of(systemMessage, userMessage));

return chatClient
        .prompt(prompt)
        .call()
        .content();
```

**Key concepts:**
- Creating a System message using `SystemMessage`.
- Creating a User message using `UserMessage`.
- Combining messages using `Prompt`.
- Passing the constructed prompt to `ChatClient`.
- Retrieving the generated response using `.content()`.

**Important:** The System message should normally appear before the User message in the prompt. The original implementation uses `List.of(userMessage, systemMessage)`. The example above corrects that ordering.

### 2. Supplying System and User Messages Directly Through ChatClient

Method: `checkPolicySecondMethod()`

Spring AI also allows System and User messages to be supplied directly through the fluent `ChatClient` API.

```java
return chatClient
        .prompt()
        .system("""
                You are an insurance assistant.
                You must NEVER reveal internal policy number,
                calculations, or internal reasoning.
                Respond ONLY with short, customer-safe messages.
                """)
        .user("""
                %s
                Customer says:
                %s
                """.formatted(CLAIM_DETAILS, message))
        .call()
        .content();
```

**Key concepts:**
- Using `.system()` to define assistant instructions.
- Using `.user()` to supply customer input and policy context.
- Building and executing a prompt using the fluent API.
- Retrieving the response as a `String`.

This approach avoids manually creating `SystemMessage`, `UserMessage`, and `Prompt` objects.

### 3. Supplying Only the User Message

Method: `checkPolicyThirdMethod()`

This approach supplies only a User message.

```java
return chatClient
        .prompt()
        .user("""
                %s
                Customer says:
                %s
                """.formatted(CLAIM_DETAILS, message))
        .call()
        .content();
```

**Key concepts:**
- Supplying input using `.user()`.
- Executing the prompt without explicitly defining a System message in this method.
- Understanding the effect of default ChatClient configuration.

**Important:** If a default System message has been configured when building the `ChatClient`, that configuration may still apply. Otherwise, this method does not explicitly provide the insurance assistant instructions used in the first two methods.

### 4. Customizing the System Message for a Request

Method: `checkPolicyFourthMethod()`

This approach demonstrates supplying different System instructions for a particular request.

```java
return chatClient
        .prompt()
        .system("""
                You are an IT Helpdesk assistant.
                So you only can answer about leave policy, Assets details.
                Apart from that, if you get any question,
                you should politely refuse to answer.
                """)
        .user("""
                %s
                Customer says:
                %s
                """.formatted(CLAIM_DETAILS, message))
        .call()
        .content();
```

**Key concepts:**
- Providing a custom System message for an individual request.
- Changing the assistant's role and response guidelines.
- Demonstrating how request-level instructions can differ from the default assistant instructions.

For example, the assistant can be instructed to behave as an IT Helpdesk assistant instead of an insurance assistant.

If a default System message is configured on the `ChatClient`, this method demonstrates supplying a different System instruction for this request.

### 5. Retrieving the Complete ChatResponse

Method: `checkPolicyFifthMethod()`

Instead of retrieving only the generated text using `.content()`, Spring AI also allows the complete response to be retrieved using `.chatResponse()`.

```java
public ChatResponse checkPolicyFifthMethod(String message) {

    return chatClient
            .prompt()
            .user("""
                    %s
                    Customer says:
                    %s
                    """.formatted(CLAIM_DETAILS, message))
            .call()
            .chatResponse();
}
```

**Key concepts:**
- Retrieving the complete response using `ChatResponse`.
- Understanding the difference between `.content()` and `.chatResponse()`.
- Accessing response metadata and other information exposed by the Spring AI response model.

| Method | Return Type | Purpose |
|---|---|---|
| `checkPolicy()` | `String` | Constructs a Prompt using SystemMessage and UserMessage. |
| `checkPolicySecondMethod()` | `String` | Supplies System and User messages through the fluent API. |
| `checkPolicyThirdMethod()` | `String` | Supplies only a User message. |
| `checkPolicyFourthMethod()` | `String` | Supplies a custom System message for the request. |
| `checkPolicyFifthMethod()` | `ChatResponse` | Retrieves the complete ChatResponse object. |

## Understanding .content() vs .chatResponse()

Spring AI provides different ways to retrieve the result of a chat interaction.

| Method | Description |
|---|---|
| `.content()` | Returns the generated assistant response as text (`String`). |
| `.chatResponse()` | Returns the complete `ChatResponse`, including the response generation information exposed by the model integration. |

Use `.content()` when the application only needs the generated text. Use `.chatResponse()` when additional response information or metadata is required.

## Configuration

### 1. Configure OpenAI API Key

Set your OpenAI API key as an environment variable.

```bash
export OPENAI_API_KEY=your-openai-api-key
```

### 2. Configure application.yml

Add the following configuration to `src/main/resources/application.yml`:

```yaml
spring:
  application:
    name: spring-openai-messagerole-poc
  ai:
    openai:
      api-key: ${OPENAI_API_KEY}
```

Ensure the Spring AI OpenAI starter dependency is included in your Maven `pom.xml`, using a version compatible with your Spring Boot and Spring AI setup.

## Important Notes: Prompt Instructions and Security

- System messages guide the model's behaviour, but they are not a security boundary.
- Never rely on System instructions alone to protect confidential information, internal policy data, or sensitive business information.
- Validate customer input and enforce authorization and business rules in the application.
- Calculate insurance eligibility, coverage limits, and claim amounts using deterministic Java business logic rather than relying exclusively on AI-generated answers.
- Treat customer-provided text as untrusted input because it may contain prompt injection attempts.
- Avoid sending actual secrets or sensitive customer information to the AI model unless the application has appropriate data protection controls.
